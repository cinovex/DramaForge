# v1.1.8 分集制作流程

把旧版的「编剧流水线 + 制作流水线 + 视频工作台」转换为当前 Toonflow 的画布操作。每步执行顺序是：**读已确认输入 → 完成本阶段 → 保存到指定画布 → 回读并检查 → 展示结果 → 等待用户确认**。聊天摘要不能代替画布成果，任务启动不能代替媒体成功。

本技能同时包含子流程和完成它们所需的专业知识。先读当前阶段的 reference，再按其中要求读取 `references/knowledge/` 的通用方法与所选类型/风格；不能仅按流程表填几个摘要就宣布完成，也不一次套用全部类型与画风。旧版依据与迁移取舍见 [来源映射](references/sourceMap.md)；不调用旧版数据库、XML 写入或子 Agent 专用接口，不自动套用其他 workflow 的模型路由。

阶段验收按 [产出契约对照](references/sourceMap.md#阶段产出契约对照) 核对内容、数量、来源映射与状态。这里保持旧版的核心产物及两条制作路线，画布存储、逐步确认和生成验收为迁移要求；不能把阶段名称相同或文件已创建当作产出一致，也不承诺两次 AI 生成逐字或逐帧相同。

## 直接粘贴剧本的短剧直通路径（默认）

用户直接粘贴/上传剧本并点击“分析剧本”，或在对话中发送完整故事要求分析时，默认按这条路径推进；不要求用户输入技能命令，不先创建一组空白画布，也不把 14 个内部步骤拆成一连串阻塞问答。使用当前项目和已打开画布，已有确认内容优先沿用。

**本直通路径优先于下文的旧版分阶段清单和项目归档约定。** 新故事默认只在用户当前项目/画布里完成分析，不要求用户手工建目录、归档多个空白画布或重复确认已给出的配置。仅当用户明确要整季归档，或已有项目本来就按剧本/资产/分集分开时，才沿用多画布结构。画布工具仍按 [画布执行](references/canvasOperations.md) 的真实 schema 使用；相关知识只按本次要完成的阶段读取，不逐项跑完旧清单。

### 一键分析执行规则

用户只需发起一次“分析剧本”。可以在后台分为故事结构、资产连续性、逐镜导演设计等有界请求，但它们属于同一个分析任务：自动续跑、显示当前进度、保存已完成检查点，最后统一回到当前项目/画布。不得在只得到故事梗概或基础分镜时提前宣布完成，也不得要求用户再手动点“深化分析”才能拿到完整提示词。失败时保留已完成内容并从缺失批次续做，不重复已完成批次。

分析完成的最低验收项：故事与逐集摘要；角色、场景、关键道具的连续性设定和可用参考图提示词；覆盖原文关键事件的全部镜头；每镜的导演设计、首帧静态提示词、视频动作提示词与真实资产映射；对镜头数量、顺序、时长、对白、资产名称和前后连续性的检查结果。任何缺项都要标成待补，不得以“已完成”遮盖。

“一步到位”指一次启动并完成整套分析，不等于自动生成媒体。分析任务只写制作规划和提示词；待故事/人物设定确认后再进入参考图批次，确认参考图后再进入视频批次，沿用下方的生成确认关口。

完整读取粘贴内容或文本附件，原文作为剧情事实来源。用户已有定稿剧本时不改写或补戏；用户给的是故事梗概时，清楚区分原文事实与改编提案。没有填写目标时长时，先按剧本中的对白、动作、停顿和场景变化估算时长并解释依据，不要求用户填目标时长表单；保留用户已给定的集数、画幅、模型和风格。叙事类型或美术风格未指定时，根据剧本提出一个有依据的建议，在故事确认点集中确认，不先发一串配置问题。长篇/多集项目先建立全剧故事与连续性总览，再只展开用户本次指定的集数，不预建大量空白集。

分析结果按一个可直接制作的项目视图组织在当前画布中，至少包含：

1. **故事与分集**：一句话故事核、主角目标/阻碍/选择/后果、三幕或适合题材的结构、原文关键事件顺序、伏笔与兑现位置；多集时逐集列集号、标题、冲突推进、角色关系变化、结尾点和预计时长。估算值不得冒充用户指定值。
2. **连续性圣经**：角色唯一身份锚点、年龄与体貌、发型/服装/配饰、声音和行为识别点；场景空间结构、固定光源与主色；关键道具及状态变化。跨集沿用同一资产记录与参考图；服装、受伤、年龄变化等剧情要求的差异建为有来源的衍生态，不复制成新人物，也不覆盖已确认基础形象。
3. **图像提示词**：角色主参考可按实际模型能力准备正面/侧面/背面/3/4 多视角图和剧情需要的表情参考；表情提示写触发原因、眼神/眼睑/眉间/嘴角/下颌/呼吸等可见变化与发生时机，不用“愤怒、悲伤”代替表演。场景图交代空间层次、出入口、固定陈设、时间和光线；道具图写清形状、材质、关键状态。每条提示都明确采用的画幅与已确认风格，不堆“电影级”空词。
4. **导演分镜**：逐场逐镜覆盖剧本中的全部关键事件，镜号连续，时间线从开场覆盖到结尾且镜头时长合计等于片段时长。每镜写叙事目的/观众可见信息、景别与构图、主体屏幕位置和朝向、机位高度/角度、焦段与景深、镜头运动起点/路径/落点、角色动作和目光、具体微表情及触发、灯光方向/质感/色温与明暗层次、台词/声音、前后镜连续状态。只描述剧情支持的细节，不为填字段新增事件。
5. **提示词和参考映射**：为资产图、需要的分镜首帧以及视频片段提供完整、可执行的提示词；按 [视频提示词契约](references/knowledge/videoPromptCraft.md#逐镜头生成提示词契约短剧默认) 写清镜号/时长、场景基调、景别/机位/构图/运镜、真实参考及人物站位、动作起止节拍、微表情变化、灯光、原文对白/声音、前后镜连续状态和必要约束。逐镜保留用户提供的动作与对白，不以“电影感/惊讶/愤怒”等抽象词代替具体画面。每镜绑定实际出现的角色、场景、关键道具和已采用首帧；按真实模型能力决定这些信息写在提示词还是节点配置，不能假称模型支持时间码/毫秒切点。优先把角色/场景参考与镜头关键帧一起传给视频模型，不把四视图拼图误当作唯一关键帧；若参考数受限，按真实能力选择最重要的身份图/场景图/首帧并注明取舍。上传外部 AI 图片后，先由用户确认或按明确的名称/节点映射到资产，后续对应镜头自动复用这些真实参考，不虚构资产 ID 或公网地址。

### 默认画布排版：三张文字卡

初次分析最多创建三张文字卡，合并相关内容，不按旧版阶段逐条建卡：

1. **故事与分集**：故事核、剧情结构、原文事件覆盖、分集大纲和时长估算。
2. **角色/场景连续性**：跨集身份锚点、造型和变化规则、场景与道具设定、资产参考图提示词及表情设计。
3. **逐镜导演分镜**：完整时间线与每镜的机位、构图、镜头运动、灯光、动作、微表情、对白/声音及真实参考映射。

不要另建“分析总结”“提示词汇总”“流程记录”“阶段检查”“制作建议”等重复文字卡；状态可写在现有卡片标题/末尾，确认点用简短聊天提问。能创建图像/视频生成节点时，把对应完整提示词直接写入该媒体节点并设置真实参考连线，让用户选中节点查看提示词；不再在旁边复制一份提示词文本卡。分析待确认期间不得启动生成。若当前画布工具不支持媒体提示词节点，才把提示词放入对应的角色/场景或镜头章节，不单独拆卡。长内容只有超过单节点或模型输出限制时才拆分，按连续镜头范围合并成少数分块，不按每个镜头单独建文字节点，也不丢内容。

分析阶段只产出规划、资产描述和可审阅提示词，不调用图片/视频生成。单集内容过长时，把完整内容分块写入当前画布的故事、资产、镜头和提示词节点，每块写后回读；聊天只交摘要与确认点，不把大量逐镜提示词挤在同一回复导致截断，也不因输出限制删镜头。完成后把故事/分集、连续性圣经、提示词及镜头表写入当前画布并回读核对；如画布工具报分页游标错误，首次读取不传游标，必要时只用新返回的游标重试一次。工具仍不可用时将分析结果直接展示在对话中，明确未写入画布，不反复调用失败工具。

### 直通路径的三个确认点

- **故事与角色确认**：一次展示故事/分集、角色与视觉设定、场景/道具清单、主要镜头结构和待决问题。用户确认前不生成图片或视频；只按用户指定内容修订。
- **参考图确认**：通过确认后再按选定模型能力给出角色/场景/道具参考图批次，写明模型、数量、分辨率、画幅、完整提示词、输入参考和已知算力消耗。对这一明确批次一次询问授权；生成后展示实际结果，等待用户选用或上传替代图。
- **视频确认**：使用已选资产与分镜首帧准备模型适配的视频提示词和真实参考顺序，核对时长、画幅、分辨率、音频与总镜头覆盖。对明确的视频批次一次说明模型、数量、时长、提示词、参考映射和已知算力消耗并取得授权，再生成、回读并展示结果。不得把“分析完成”或“自动排布”当成媒体生成授权；用户已经授权的同一批次不重复询问。

v118workflow 是全流程的主技能；workflow 仅在实际选择 Seedance 2.0/2.5 并进入视频提示词阶段时补充其专用连续性、表演、时序和模型格式规则。其他模型不读取或强套 Seedance 模板。

## 先定位进度与画布

1. 确认当前项目、用户本次目标、已有输入与已确认结果。直通路径将用户提供的完整剧本原样保留在当前项目画布的正式文本节点，再分析，不倒推虚构小说、事件表或骨架；正式多画布项目才写入对应剧本总画布。续作从首个未确认阶段继续。
2. 对“直接粘贴剧本”的默认直通路径，核实当前项目和激活画布，读取当前画布工具的真实 schema，沿用现有节点；不要为了套用旧流程要求先把剧本另存到新画布。只有用户明确要求正式多画布归档或项目已采用该结构时，才读取 [项目初始化与归档](references/projectSetup.md)；需要读写画布时按 [画布执行](references/canvasOperations.md) 操作。
3. 直通路径默认把本次故事、资产设定、分镜和提示词组织在**当前项目画布**；长篇多集先维护一个跨集连续性总览，按用户指定逐集展开。只有正式多画布项目才使用下列结构：

```text
项目工作区/
└─ 画布/
   ├─ 剧本.json
   ├─ 资产.json
   └─ 分集/
      ├─ 第001集.json
      ├─ 第002集.json
      └─ …
```

| 画布 | 唯一正式内容 |
| --- | --- |
| 剧本 | 项目配置、来源索引、章节事件、故事骨架与分集大纲、改编策略、各集正式剧本、画布路径索引 |
| 资产 | 全剧基础与衍生资产、父子关系、视觉设定、提示词、已选图片、使用集数 |
| 第 N 集 | 本集剧本来源/工作快照、导演规划、分镜表、参考素材节点、分镜图、视频、选用与交付记录 |

分集画布里的图片是同一资产文件的本地引用，不是另一套正式资产库。跨画布不能直接连边；先切换读取真实资产输出，再在本集建立引用节点。素材文件保留宿主返回的位置，不能为了整理画布文件夹而搬动 `assets/` 中的生成结果。

当前 `addCanvas` 没有目录参数。必须按 [画布归档办法](references/canvasOperations.md#画布创建与归档) 完成文件树归位、重新发现真实路径/ID后再填入成果，不能把所有画布留在根目录便宣布归档完成。

## 主流程与确认关口

下表是正式多画布项目或用户明确要求完整分阶段归档时使用的扩展路线。普通新故事按上方“直接粘贴剧本的短剧直通路径”一次完成分析阶段所需成果，并使用其中三个确认点；不能因为表格列有 14 步，就把用户拉进 14 次问答或提前建立全部节点。

每行是独立阶段，执行前读取该行 reference 及其指定的知识。已有明确确认的产出可复用并记录来源；“跳过”必须有适用理由和用户明确选择。项目不涉及原著改编时，章节事件、骨架或策略可按已有输入缩短或跳过，不能凭空补造经历。

| 步骤 | 子流程 | 成果落点与本次需要确认的结果 |
| --- | --- | --- |
| 0 | [项目初始化](references/projectSetup.md) | 剧本画布：项目配置、范围、文件夹与画布索引 |
| 1 | [来源与章节事件](references/sourceEvents.md) | 剧本画布：实际章节与事件表；确认来源覆盖与事实 |
| 2 | [故事骨架](references/storySkeleton.md) | 剧本画布：故事核、人物弧、分集大纲、删减记录；确认分集方案 |
| 3 | [改编策略](references/adaptationStrategy.md) | 剧本画布：改编原则与边界；确认取舍 |
| 4 | [逐集剧本](references/episodeScript.md) | 剧本画布：本集完整剧本；默认一集一确认，再决定续写哪集 |
| 5 | [基础资产提取](references/baseAssets.md) | 资产画布：角色/场景/道具及出场集；确认复用、新建与视觉设定 |
| 6 | [资产图片制作](references/generateAssets.md) | 资产画布：基础资产提示词与图片；先确认生成方案，再确认采用图片 |
| 7 | [导演规划](references/directorPlan.md) | 当前集画布：分场、台词统计、情绪、过渡与注意事项 |
| 8 | [衍生资产分析](references/deriveAssets.md) | 资产画布：本集衍生清单与父资产；确认全部、部分、调整或跳过 |
| 9 | [资产图片制作](references/generateAssets.md) | 资产画布：已选衍生图片；无衍生需求时明确记录跳过 |
| 10 | [分镜表](references/storyboardTable.md) | 当前集画布：场→片段→镜头、真实资产映射及检查结果 |
| 11 | [分镜面板落点](references/storyboardPanel.md) | 当前集画布：按实际模式建立文本、参考、图像/视频节点；确认数量、时长与连线 |
| 12 | [分镜图片](references/storyboardImages.md) | 当前集画布：首帧模式的分镜图；纯文本多参模式可跳过，须记录原因 |
| 13 | [视频与交付](references/videoProduction.md) | 当前集画布：视频提示词/配置 → 生成结果 → 选用与交付，三个独立确认关口 |

第 7–13 步每集循环。完成本集后让用户选择继续哪集；不要把“一集完成”理解为全剧已完成。基础资产可按已确认的剧本分批补齐，跨集仍在同一资产画布维护。

叙事类型决定如何组织信息、情绪和镜头，美术风格决定形态、材质、色光和表现方式，两者独立选择，不把“悬疑”当画风或把“黏土”当剧情类型。用户已有明确选择就沿用；未选择时依据内容提出有理由的方案，确认后写入项目配置。

知识不是额外的剧情授权。编剧阶段可在用户允许的改编范围内使用结构与反转方法；剧本定稿后，类型技法只指导已确认事件的表现，不得新增红鲱鱼、改结局、交换事件顺序或自行加戏。风格示例也不能覆盖已确认角色身份、世界观和参考图。

通用方法、类型特例和历史模型模板冲突时，先满足用户已确认内容及当前工具真实能力，再采用匹配本项目的方法。旧版单线快节奏、固定镜长、肤色/身高模板等不强套所有项目；商业短剧、群像、留白和特殊变体的适用条件见各知识文件。

每次只把**本项目实际采用的方法及结果**写入对应画布：例如本场隐藏哪条线索、角色为何保持侧身、场景主光从哪来、父图哪些特征不变。不要把整本知识文档复制成节点，也不要仅记录“已参考某技能”而没有可审阅的制作决策。

## 每一步如何确认

- 先把本阶段完整可审阅结果写入画布，通过工具回读确认已保存；文本较长可按章节、集、场拆节点，不截断正式内容。用 `fitCanvas` 展示本次结果。
- 仅正式多画布路线使用独立「阶段记录」节点。在默认直通路径里，把当前确认状态简写在现有“故事与分集”卡末尾，禁止为记录流程状态再建文字卡。状态区分 `草稿`、`待确认`、`已确认`、`生成中`、`失败`、`待复核`、`已跳过`。
- 展示画布名称及相对路径、成果摘要、具体问题、下一步内容。用可用的 `askUser` 让用户选择“确认进入下一步 / 修改指定项 / 重做当前步”；没有提问工具时在对话中提问并等待。用户回复之前结束本阶段，不提前创建下阶段制作节点或触发媒体生成。
- 用户答复后记录其决定。只修改用户指定项，回读修订结果再确认；不要把检查通过、提问取消、跳过问答、超时或沉默视为批准。“继续”只推进当前待确认的下一阶段。
- 用户已经明确确认的配置、资产或具体生成批次继续有效，不重复索取同一授权。若用户明确授权多集同阶段批次，可以按该范围执行并集中展示；没有这种授权时仍逐集确认，不把整项目目标当作全流程放行。
- 生成方案应包含实际模型/模式、对象与数量、提示词、参考、时长/画幅/分辨率及已知费用；未知费用标明未知。仅在当前批次范围得到确认后调用生成。失败后先核对真实状态，额外候选、改模型或收费重试不得超出已确认范围。

## 续作、修改与失败

每次续作以画布内容及用户确认记录为准，不只依赖聊天记忆。已有结果缺少确认时，先展示已有结果补确认，不重新生成。

改动上游后标出实际受影响的下游：剧本变化检查本集导演/分镜/视频，资产版本变化检查引用该资产的分镜/视频。将它们标为待复核，保留原成果与选用记录，不自动全剧重做。未受影响的确认继续有效。

来源缺失、目录未归位、工具缺失或写入失败时，说明具体未完成项和恢复步骤。不得将聊天文本、空节点、假文件路径、旧输出或任务已启动包装成阶段完成。只处理用户本次要求的范围；仅咨询或编辑技能时不创建制作项目。
